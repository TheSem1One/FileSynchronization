# FolderSync

**FolderSync** — це надійна консольна утиліта на C# (.NET 10) для односторонньої періодичної синхронізації вмісту двох папок:

$$\text{Source} \longrightarrow \text{Replica}$$

Після кожного проходу синхронізації стан директорії `Replica` повністю відповідає стану директорії `Source`:
- нові файли копіюються з Source в Replica;
- змінені файли оновлюються на основі порівняння вмісту (SHA-256);
- збережена повна вкладена ієрархія папок;
- файли та папки, відсутні в Source, безпечно видаляються з Replica;
- директорія Source ніколи не модифікується;
- усі операції логуються одночасно в консоль та у файл журналу.

## 1. Архітектура та структура проєкту

Проєкт реалізовано згідно з принципами Clean Architecture / Separation of Concerns та YAGNI без зайвих зовнішніх бібліотек:

```text
FolderSync/
├── src/
│   ├── FolderSync.Console/           # Точка входу CLI, розбір аргументів, керування таймером
│   │   ├── Program.cs
│   │   ├── ArgumentParser.cs
│   │   └── Services/
│   │       └── FileLogger.cs         # Реалізація логера (консоль + файл)
│   │
│   └── FolderSync.Core/              # Доменна логіка, валідація та алгоритм синхронізації
│       ├── Interfaces/
│       │   └── IFileLogger.cs        # Контракт логування (Dependency Inversion)
│       ├── Models/
│       │   ├── SyncOptions.cs        # Модель налаштувань
│       │   └── SyncResult.cs         # Результати синхронізації
│       ├── Services/
│       │   └── FolderSynchronizer.cs # Основний сервіс синхронізації
│       └── Validation/
│           └── SyncOptionsValidator.cs # Перевірка шляхів та налаштувань
│
├── tests/
│   └── FolderSync.Tests/             # Автоматичні тести xUnit
│       ├── ArgumentParserTests.cs
│       ├── SyncOptionsValidatorTests.cs
│       ├── FolderSynchronizerTests.cs
│       ├── FileLoggerTests.cs
│       └── Helpers/
│
├── FolderSync.sln
└── README.md
```

### Основні архітектурні рішення

| Рішення | Обґрунтування |
|---|---|
| **Платформа** | .NET 10 |
| **Порівняння файлів** | Потоковий **SHA-256** з попередньою перевіркою довжини файлу |
| **Атомарне копіювання** | Копіювання в тимчасовий файл `.sync_tmp_*.tmp` з наступним `File.Move(..., overwrite: true)` |
| **Періодичність** | `PeriodicTimer` у Console-проєкті (не блокує та не змішується з логікою синхронізатора) |
| **Коректна зупинка** | Обробка сигналу `Ctrl+C` через `CancellationTokenSource` |
| **Безпечне видалення** | Якщо читання/сканування Source зазнає помилки, фаза видалення в Replica пропускається для уникнення втрати даних |
| **Тестування** | Повний набір тестів на базі **xUnit** з ізольованими тимчасовими папками |

## 4. Використання та запуск

Формат команди:

```bash
dotnet run --project src/FolderSync.Console -- <source-path> <replica-path> <interval-seconds> <log-file-path>
```

Або через зібраний бінарний файл `FolderSync.Console.exe`:

```bash
FolderSync.Console <source-path> <replica-path> <interval-seconds> <log-file-path>
```

### Параметри командного рядка:

1. `<source-path>` — шлях до вихідної директорії (Source). Повинна існувати.
2. `<replica-path>` — шлях до папки-копії (Replica). Створюється автоматично, якщо не існує.
3. `<interval-seconds>` — період синхронізації в секундах (додатне число, наприклад `10`).
4. `<log-file-path>` — шлях до файлу логу (створюється разом з необхідними папками).

### Приклад запуску:

```bash
dotnet run --project src/FolderSync.Console -- ./my_source ./my_replica 10 ./logs/sync.log
```

Перша синхронізація виконується **негайно** після старту, наступні — щойно спливає інтервал (наприклад, кожні 10 секунд).

Для зупинки натисніть **Ctrl+C**. Програма дочекається завершення поточної файлової операції та коректно завершить роботу.

## 6. Безпека та обмеження

1. **Захист від зациклення та перекриття шляхів**:
   - `Source` і `Replica` не можуть бути однією і тією ж папкою.
   - `Replica` не може знаходитися всередині `Source`.
   - `Source` не може знаходитися всередині `Replica`.
   - Перевіряється захист від Path Traversal.
2. **Захист від випадкового видалення**:
   - Якщо під час читання папки `Source` виникла помилка (відсутність прав, недоступний диск тощо), статус позначається як неповний і етап видалення файлів у `Replica` **скасовується**.
3. **Reparse points / Symbolic links**:
   - Символічні посилання та junctions пропускаються з попередженням у журналі для запобігання нескінченної рекурсії або виходу за межі цільових директорій.
4. **Обробка блокувань файлів**:
   - Якщо конкретний файл зайнятий стороннім процесом, помилка фіксується у лозі, а програма продовжує обробку інших файлів.
